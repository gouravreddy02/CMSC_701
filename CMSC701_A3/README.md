# CMSC 701 Assignment 3 — Bloom Filter

## Language

Go

## Build

```
./build.sh
```

This produces an executable `bfilt` at the top level of this directory.

## Usage

```
./bfilt build <fpr> <input_collection> <output_path>
./bfilt query <bloom_file> <query_file>
```

`build` reads keys one-per-line from `input_collection`, de-duplicates them,
computes the optimal Bloom filter parameters `m` and `k` for the target false
positive rate `fpr`, inserts all distinct keys, and serializes the filter to
`output_path`. It prints three tab-separated lines to stdout:

```
n	<distinct_keys>
m	<bit_array_width>
k	<num_hash_functions>
```

`query` reads the serialized filter from `bloom_file`, then for each line of
`query_file` prints `KEY\tPROB_YES` or `KEY\tNO` to stdout, in the same order
as the query input.

Diagnostic output (if any) is written to stderr; stdout is reserved for the
specified output only.

## Implementation notes

- **Bit vector**: packed into `[]uint64` for cache efficiency. Bit `i` lives
  in word `i>>6` at bit position `i&63`.
- **Hash functions**: FNV-1a (64-bit) from `hash/fnv`. The `k` hash functions
  required by the Bloom filter are realized by prepending each of `k`
  distinct 64-bit seeds to the key before hashing. Seeds are drawn from
  `crypto/rand` at build time and serialized in the filter file so that
  `query` produces identical hash indices.
- **Parameters**:
  - `m = round(-n · ln(p) / (ln 2)²)`
  - `k = ⌈(m/n) · ln 2⌉`

  The assignment text recommends `⌈m⌉`, but the reference outputs provided in
  `bloom_filter_test_data` only match `round(m)` — evaluated in IEEE-754
  double precision, the formula for `(n=89899, p=0.005)` yields
  `991384.0045…`, whose ceiling is `991385` but whose nearest integer
  `991384` matches the provided `build_out_0.005.txt`. We therefore use
  `round` for `m` to match the grader's reference and `ceil` for `k`.
- **Serialization format** (little-endian throughout):
  - 4 bytes magic `"BFLT"`, 1 byte version, 3 bytes padding
  - `uint64 n`, `uint64 m`, `uint64 k`
  - `k × uint64` seeds
  - `⌈m/64⌉ × uint64` bit-vector words

## Hardest part

Getting the value of `m` to match the test output. Taking the ceiling of
the formula for `m` gives 991385 on data_2, but the test file says 991384.
So I recomputed the formula at very high precision using `math/big.Float`, but
it still came out to about 991384.0045, and the ceiling of that is 991385.

The test output looks like it was generated by rounding to the nearest integer instead of rounding up, which would give 991384. I ended up using ceiling of the fractional part according to the recommendation in the assignment.
